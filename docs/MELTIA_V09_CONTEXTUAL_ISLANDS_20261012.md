# Meltia v0.9 — 複数英語区間の文脈的な経路評価（2026-10-12）

> **状態**：研究版・Draft PR [#8](https://github.com/Fugu0141/Meltia/pull/8)。
> 独立Coreの開発版番号 `0.9.0-dev`。**IME・TSF・アプリには未接続**。
> ベースはv0.8 Draft PR #7。v0.7 → v0.8 → v0.9 はそれぞれ別の開発ブランチ。

## 背景と目的

v0.8の既存研究語彙を使った530件の合成試験で、Top1は177→250件、
Top-Kは332→405件へ改善した。一方、**2英語区間・3英語区間の独立Top1は
それぞれ0/54件**。候補を多数生成できても、英語1区間でまとめた誤経路や
英語の一部を日本語ローマ字として残す経路が上位に並ぶことがある。

## v0.9の変更

`MeltiaContextualIslandScoring` は**独立の小さな経路スコアリング関数**。
2つの英語候補が次の条件を同時に満たす場合だけ、
その2区間を含む**完成済みルート**に助詞境界の追加証拠を与える。

- 2区間が重ならず、各区間はASCII英語表記5文字以上。
- 両区間の間が`no`、`to`、`de`、`ga`、`ni`、`wo`、`ha`という
  2文字の日本語ローマ字助詞。
- 両候補の綴り全体は通常の日本語ローマ字では読めない（独立英語の手がかり）。
- **長い日本語ローマ字として読める前後5文字以上の部分**を含む候補は除外する。
  日本語の接続詞や文章部分を英語候補に飲み込む誤経路を減らすため。
- 適用する追加加点は**3.0**（英語区間1つ追加のコスト4.5より低い）、候補それぞれには加点しない。
  **候補単体の順位やOrigin、必須ロックの扱いを変更しない**。

切替は研究用オプション（既定OFF）:

```csharp
var engine = new MeltiaBoundaryEngine(new MeltiaBoundaryOptions(
    ExperimentalUnknownLatinCandidates: true,
    ExperimentalPhoneticLatticeDecoder: true,
    ExperimentalContextualIslandScoring: true));
var result = engine.Analyze("kinouhastrategynorequirementtoiu");
System.Diagnostics.Debug.Assert(!result.AutoCommitAllowed);
```

v0.8の比較モデルは`ExperimentalContextualIslandScoring: false`。
同じ語句はどちらでも同じ候補集合から解析する。

**意味的な限界**：短い日本語助詞が綴りの途中に偶然含まれていても
英語境界があるとは断定できない（例：「tokyo」単独は日英の意図が曖昧）。
未知の日本語全体で誤英語分割がないという保証はない。
助詞以外の接続（空白なし、同一綴り・連続英語、固有名詞など）では
この局所信号だけでは判断できない。

## 品質管理と評価

- v0.7/v0.8/v0.9の同条件モデルを、研究済み47ケースと530ケースに同時実行。
- **別の英語40語＋日本語ローマ字18種を使う290件の追加合成評価**を実施。開発時に語彙を確認しているため盲検ではない。
- 3モデル間で**候補集合の完全同一性**を1入力ずつ検査。
- 47件中5件、530件中152件、追加290件中90件の合成日本語のみ入力で、Top1誤英語が既定の比較方式を超えたらCI失敗。
- **47件・530件についてはv0.8のTop1/Top-K完全一致件数を4条件それぞれで下回るとCI失敗**。追加290件は最適化対象にせず、回帰の診断を表示。
- 比較対象：Gold候補包含率、Top-K、Top1、英語領域、切替F1、失敗の段階、
  複数区間、例外、再現性。過去データに合わせた閾値を後付けしない。
- 47+530は**これまで研究に使った英語語彙を多く共有する合成データ**。
  新しい自然文による人手ラベル付きholdout、実打鍵、メモリ・速度測定が必須。

## 実測結果

[初期評価CI](https://github.com/Fugu0141/Meltia/actions/runs/38200721878)では、
助詞境界を一律4.5点で加点した初期モデルが **530件のTop1独立条件で250→218件に退行**。
そこで、長い日本語ローマ字の前後を取り込んだ候補を除外し、加点を3.0点に低減した。
失敗試験を隠さず、この試行は失敗例として保持する。

[修正後の47件・530件CI](https://github.com/Fugu0141/Meltia/actions/runs/38200879428)（成功）：

| モデル | v0.8：530件Top1 | v0.9：530件Top1 | 改善 |
|---|---:|---:|---:|
| 辞書／Meltype予測なし | 250 | **273** | +23 |
| 英語辞書のみ | 301 | **315** | +14 |
| Meltype予測のみ（独立評価ではない） | 314 | **326** | +12 |
| 辞書＋予測（独立評価ではない） | 300 | **313** | +13 |

**主要な目標の進捗**：旧研究語彙を使う530件の中で、辞書／Meltype予測なしの
2英語区間Top1は **0/54→14/54**、3英語区間は **0/54→9/54**。
Top-Kは2英語区間 **22/54→28/54**、3英語区間 **18/54→19/54**。
日本語のみR08の152件は両方とも152/152件正解、Core47件の5件も全件正解。

47件では、独立Top1は**25/47→25/47**（変化なし）。スコアの改善だけで
一般的な入力の精度が高まったと断定しない。

## 追加290件：研究済み54語とは異なる語彙を使用

[追加評価を含むCI](https://github.com/Fugu0141/Meltia/actions/runs/38201076610) 成功。
`GeneralizationCorpus.cs` は旧研究の54英語語種を避けた**別の英語40語**を、
英語のみ・混在1区間・混在2区間・混在3区間・大文字開始の5種
（40×5＝200件）へ展開する。追加で日本語ローマ字18種×5＝90件を作成。
すべてゴールドをテキスト断片から生成する**合成テスト**であり、
作成者が語彙を選んでいるため、完全な盲検や自然文のholdoutではない。

| 条件（290件） | v0.8 Top1 | v0.9 Top1 | v0.8 Top-K | v0.9 Top-K |
|---|---:|---:|---:|---:|
| 辞書／Meltype予測なし | 156 | **167** | 220 | **230** |
| Meltype辞書のみ | 160 | **167** | 209 | **223** |
| Meltype予測のみ | 171 | **180** | 228 | **234** |
| 辞書＋予測 | 168 | **175** | 212 | **226** |

2英語区間の独立Top1は**8/40→14/40**、3区間は**5/40→10/40**、
日本語のみの90件は両版で90/90件正解だった。

CIの非退行ゲートは、各スイート（47・530・290件）・各4条件で、
**v0.9がv0.8のTop1件数とTop-K件数をどちらも下回らないこと**を検査する。
さらに個別入力で候補区間集合がv0.8から変化していないこと、合成日本語のみの
予測が従来より悪化しないことを検査する。

**検証上の限界**：追加語彙には比較的長く英語特有の文字列が多く、
日英双方に読める短い未知語、実際の誤打鍵、生活会話の文章、地域固有名詞などの
汎化は証明していない。Gold意図は人工的に構成したもので、人手収集の未知文章ではない。

## 未解決課題と採用可否

- 2区間・3区間は依然として各54件中40件・45件がTop1不一致。
- `tokyo`など日本語としても読める英語表記は、ユーザー意図なしに決定できない。
  現在は**日本語優先を維持**し、明示英語ロックで意図を示す。
- 知らない単語の部分区間を大量に候補化するv0.7の弱点は未解決。
- 新しい文脈・語彙・自然文に対して偽英語選択が増えないかは、
  追加290件と最終的な**人手確認済み自然文の独立評価**が必要。
- IME、TSF、リアルタイム連続打鍵は一切変更していない。
