# H11修正計画：H10の103ケース評価から語・音韻の同時分割へ（2026-10-14）

## 要件と課題の再定義

PR #34のH10試作を既定ONにしてはならない。47件＋56件＝103件のMeltype Issue診断でH10は54/103の英語区間Top1一致だったが、非英語21件のうち8件に誤英語区間を付けた。特に英語＋ローマ字助詞、短い英語と日本語、英字の内部での切断、数字・識別子、単独日本語の読み崩れ、長文での処理時間が課題。

## 設計判断

- **候補は証拠であり決定ではない**。辞書に載る`new`でも「ねw」という意図を否定できない。ロック・文脈なしでrawが同じ場合は限界を明示。
- **日本語の音節解析を英単語の語彙判定と独立させる**。H10では短い英字区間が多数生まれ、局所点の和で不要な英語が勝ちやすい。H11は「日本語音韻として自然か」と「英語の語としてまとまっているか」を候補単位で比較する。
- 既存の英語辞書を追加するため、H10→H11の差は**アルゴリズム＋固定辞書の証拠**の差である。モデル単体の改善とは主張しない。辞書にある語やIssue由来の評価例に限って良い結果でも、未知語に一般化するとは限らない。
- 個別Issueのgoldに合わせた例外（`if raw == ...`）は追加しない。
- 文書・評価コードをPR #34へ併せてコミットし、別並列PRのファイルを変更しない。

## 検証ゲートと移植判定

1. **ビルドゲート**：.NET10で既存Coreテスト・旧H10テスト・新H11契約テストがPASS。
2. **安全ゲート**：明示ロック／URLメール／Unicode保持／決定性／編集時の非自動確定。
3. **品質ゲート**：EN-OOV、SEAM、JA-PROTECT各群のTop1、JA誤英語、Top-K、候補の有無を並列比較。合計Top1だけの改善を採用判断に使わない。
4. **性能ゲート**：短文だけでなく長文・連打・編集のベンチマークとWindows実キーE2E。現段階では未実施。
5. **holdoutゲート**：同じIssueデータをパラメータ調整に使ったら独立評価にはならない。独立収集した自然文、人手で意図を確認した対照ケースで再検証。
