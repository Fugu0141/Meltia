# Meltia v0.8 — 日本語音韻経路と未知英語候補の同時探索

**状態: 実験専用 / 正式リリースではない / IME未接続。**

## 問題と変更の狙い

v0.7で生成する未知英語候補の包含率は上がったが、530件の合成評価で
候補が存在するのに正解Top1にならないケースが多かった。
v0.7は候補間を単純な「日本語らしい文字列」として丸ごと無償スキップできるため、
**正しい日本語ローマ字として読めない残り文字**を残す経路にも同じ価値を与えていた。

v0.8では、**日本語として解析する区間と英語候補を同じ格子上で探索**する。

- 日本語の平仮名入力に相当する部分は、ローマ字として読める**最大8文字の可変長エッジ**で遷移。1文字あたり**0.25点**を加点し、英語候補が日本語の接尾部分を過剰に飲み込むケースを抑える。
- ローマ字として読めないASCIIは「読みが不明な一文字」を表す有料エッジ（初期値3.5点の減点）で回復。
- 英語候補はv0.7の候補とスコアを**一切変更せず**に利用。英語区間コストは4.5点で保守的に扱う。
- 読みやすい日本語と区切ったとき残りに不正な英字が少ない候補が、相対的に上位になりやすい。
- Top8の経路探索は0/1/2/3/4以上の英語span本数の多様性をまず保持し、残りを得点順に埋める。Top1は最終的に得点順。多区間の正解経路を保証するものではない。
- 1字ずつの確定を伴わない読み取り専用解析で、実際の変換・確定・ユーザーデータへ干渉しない。

研究用オプション:

```csharp
var engine = new MeltiaBoundaryEngine(new MeltiaBoundaryOptions(
    ExperimentalUnknownLatinCandidates: true,
    ExperimentalPhoneticLatticeDecoder: true));
var result = engine.Analyze("kinouhastrategynorequirementtoiu");
// 経路Top-Kはプレビュー診断専用。確定には使用できない。
System.Diagnostics.Debug.Assert(!result.AutoCommitAllowed);
```

**v0.7のままにしたい場合は** `ExperimentalPhoneticLatticeDecoder: false` を使う。
未指定は既定でfalse。本番Windows TSFにも未接続。

## 後方互換性・計算量

候補生成はv0.7の`MeltiaUnknownLatinCandidates`と同じコードを使う。
必須英語ロック、URL・メール保護、明示日本語ロック、Unicode UTF-16ペア、
最大1024単位の原文、128件の候補、8件のTop-Kを維持する。
各始点における日本語の最大8文字をキャッシュするが、
候補ラティスのDPは最大8経路に枝刈りするため網羅探索ではない。

ローマ字の成立チェックは既存`MeltiaRomaji.CanRead`を使用し、
日本語語彙や同音異義語・実際のIME辞書の正解を保証しない。
先行する日本語が曖昧な単語（例`tokyo`）の場合も、
ユーザーの明示指定や文脈が無ければ意図を決定できない。
本方式が識別できない入力は「原文を保持して候補に留める」設計を維持する。

## 比較設計・採用基準

同じ47件および530件の合成意図ラベル付きデータを、
`Meltia-v0.7-*`と`Meltia-v0.8-*`の4条件で比較:

1. 独立（Meltype判定も辞書も使わない）
2. 同じMeltype埋め込み英語辞書を使う
3. Meltypeシャドー予測を参考にする（独立精度ではない）
4. シャドー予測と辞書を両方使う（独立精度ではない）

各条件で日本語だけの負例数、正解候補包含率、Top-K・Top1の完全一致、
英語区間の合算と各入力の失敗段階を記録する。
先行研究と同じ語彙のため、この530件は**盲検の自然文holdoutではない**。
アルゴリズムが改善したと判断する際には少なくともTop1、曖昧入力の被害、
コスト（遅延・メモリ）を同時に見る。合成データの得点に合わせて
事後的に閾値を調整しても、未知文章での精度証明にはならない。

正式採用までの未完了項目: 実測の逐次打鍵・Windows TSF・IME統合、
実時間遅延p95/p99、文字モデルの独立holdout、手作業goldの一般化試験。

## 実測結果（合成47件＋530件、2026-10-12）

[GitHub Actions評価実行](https://github.com/Fugu0141/Meltia/actions/runs/38187830950)（`20a6abc7`、成功）。

### 530件：Top1英語span完全一致

| モデル条件 | v0.7 | v0.8 | 変化 |
|---|---:|---:|---:|
| 辞書・Meltype予測なし | 177/530（33.4%） | **250/530（47.2%）** | **+73件** |
| Meltype埋込英語辞書のみ | 251/530 | **301/530** | **+50件** |
| Meltypeの読み取り専用予測のみ | 269/530 | **314/530** | **+45件** |
| Meltype辞書＋予測 | 263/530 | **300/530** | **+37件** |

辞書・Meltype予測なしTop-K完全一致は **332→405/530**。
47件でも同条件のTop1は **12→25/47**、Top-Kは **25→30/47**。
v0.8の差分はルート探索・評価部分のみで、**候補本数およびgold候補span包含率は
v0.7から一切変わらない**（530件の独立条件で候補12,263本、gold候補包含率93.5%）。
従って、候補漏れへの対策ではなく、候補を選ぶ性能の変化を測定した。

### 故障段階と不十分な点

530件・辞書／Meltype判定なしの場合：

| 故障段階 | v0.7 | v0.8 |
|---|---:|---:|
| Top1正解 | 177 | **250** |
| Gold英字候補が欠落 | 34 | 34 |
| Gold候補は全てあるがTop-K内に正解経路なし | 164 | **91** |
| Top-Kに正解経路はあるがTop1で不正解 | 155 | 155 |

難しい複数英語区間の内訳（各54件、辞書・Meltype予測なし）：

| 合成分類 | v0.7 Top1 / Top-K | v0.8 Top1 / Top-K |
|---|---:|---:|
| 英語2区間 | 0/54・0/54 | **0/54・22/54** |
| 英語3区間 | 0/54・0/54 | **0/54・18/54** |

**2区間・3区間のTop1はまだ0件**。日本語と英語の見かけ上の音韻可読性が衝突する入力で、
複数の正しい英語区間を同時採択できる順位付けが未完成。
例 `kinouhastrategynorequirementtoiu` は正しい2候補を両方生成するが、
正解2区間の組み合わせがTop8へ残らない。次版では局所文字モデル／文脈と複数区間の
整合的なスコアを組み合わせることが必要。

日本語のみのR08 152件とS11 5件はv0.8独立モデルで全件日本語。
英語のみ・日本語混在の精度改善だけで採用判断できず、
`tokyo` / `ime` の意図曖昧性や未知自然文の再評価は必須。

### 解釈の注意

評価は**人工的に接続した合成テキストで、語彙は過去研究と共通**するため、
盲検holdoutではない。今回の数値だけで日常入力性能を保証せず、
辞書とMeltype判定を利用する行は独立性能と混同しない。
本体Windows IMEへの接続、TSFの逐次入力、遅延p95/p99、メモリ、IME変換精度は未測定。
正式リリースや本番適用を行っていない。
