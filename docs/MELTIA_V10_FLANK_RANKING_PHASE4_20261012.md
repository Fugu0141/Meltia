# Meltia v1.0 フェーズ4：日本語ローマ字の吸収を抑制する局所スコアリング

> 2026-10-12 / **独立Coreの実験・既定OFF・正式版ではない**。
> これまでのフェーズ3と比較することで、実測に基づき採否を決める。
> Windows TSFやMeltypeの入力処理には接続しない。

## 課題

旧v1.0は未知英語の候補列挙、128候補選別、Top-K経路探索を段階的に改善したが、
英語候補が例えば `nihongocompiler` 全体を覆うと、
日本語ローマ字 `nihongo` を英語として**飲み込んだ候補**も
Top1/Top-Kの競合に残り得る。正解は入力者の意図による。

今回のフェーズ4では、候補を削除せず、未知英語仮説が
**長く独立した日本語ローマ字の接頭・接尾部分**を含む場合にだけ
局所減点し、境界を切り分ける解釈を相対的に有利にする。

## アルゴリズム

`MeltiaBoundaryOptions.ExperimentalJapaneseFlankScoring`
は**既定false**。有効にするには
`ExperimentalPhoneticLatticeDecoder=true`を要する。

- 対象は`v0.7-unknown-latin-provisional`の候補のみ。
  明示英語ロック、URL、メール、辞書、Meltypeの候補は減点しない。
- すべてASCII英字の未知候補の**先頭または末尾7文字以上**に、
  `MeltiaRomaji.CanRead`で日本語として読める断片があり、
  残りが**5文字以上かつ日本語として完全には読めない**場合、
  片側につき `-3.0`、両側なら `-6.0` を追加減点する。
- 例えば `nihongocompiler` の全体英語候補は
  `nihongo` + `compiler` と分割できるので、
  全体の未知英語仮説のみ減点する。
- 短い `no`/`to` といった日本語助詞**だけでは減点しない**。
  `tokyo`、`ime`のような読みの曖昧な語を文字列だけで決めない。
- 得点調整は経路探索にのみ入れ、候補集合・候補スコアを変更しない。
  `MeltiaPhoneticLatticeDecoder`では候補ごとの補正値を一度だけ
  先に計算し、ビーム探索の枝展開で再利用する。
- 日本語のみ、UTF-16絵文字、明示言語指定、URL保護、
  `AutoCommitAllowed=false`の契約は維持する。

### 採用リスク

この減点は英語辞書の証拠なしに意図を推測する**ヒューリスティック**であり、
例えば `nihongocompiler` が本当に一つの英語固有名詞なら
**正解の英語候補を減点してしまう**。
自然文での性能向上、スコア差の確率的解釈、
英語語彙の汎化を保証しない。

そのため既定OFFで比較し、入力意図が曖昧なものはユーザーによる
明示指定を優先する。

## 比較実験

既存の合成評価は47＋530＋290＋56＋60＋36＝**1019件**。
フェーズ4では新たな48件を追加し、合計**1067件**の
独立目的別・合成意図ラベル付き試験にする。

`FlankScoringCorpus.cs`は英語12語×以下の4文型：

| 区分 | 各12件の目的 |
|---|---|
| F01 | 日本語7文字の後に英語 |
| F02 | 英語の後ろに日本語7文字 |
| F03 | 英語の前後両方に日本語 |
| F04 | `nihongo`+英語を一語の英語固有名詞と仮定する逆境例 |

**F04は一般的な英語単語の収集結果ではなく、悪化可能性を示す意図的な反例。**
正誤は人為的なゴールドラベルであり、自然言語の盲検評価ではない。

次の4条件で既存フェーズ3と今回のフェーズ4を同一ケース比較：
1. 辞書・Meltype参照なし（独立）
2. Meltype内蔵辞書（外部根拠あり）
3. Meltypeシャドー予測参照（独立ではない）
4. 内蔵辞書とMeltype予測参照（独立ではない）

`Phase4FlankImpact`では、
**Top1を新しく正しくした件数、逆に誤った件数、Top-K内の正解経路復活・喪失、
日本語のみの誤検出数**を区別して記録する。
全件・全4条件で**候補集合がフェーズ3と完全一致**することを契約テストにする。
マイナス事例を削除せず採用判断に含める。

## 性能・ローカル実行

.NET SDK 10およびPython 3.10以降が利用できるリポジトリルートで：

```sh
dotnet run --project tests/Meltia.Core.Tests/Meltia.Core.Tests.csproj -c Release
dotnet run --project tests/Meltia.BoundaryEvaluation/Meltia.BoundaryEvaluation.csproj -c Release -- --output artifacts/meltia-flank-48.json --suite flank
python tools/run-meltia-quality.py --tier full
```

`full`には既存1019件と新48件の評価を含む。
性能ベンチでは、接頭だけ・接尾だけ・両側の日本語吸収ケースを追加し、
フェーズ3と4のp50/p95/p99および割当量比を比較する。
これはWindows TSF逐次入力の遅延ではない。

## 現時点の評価

1067件の試験と性能測定は未実行・未検証。**

統計的妥当性と日本語誤検出を継続調査する。
